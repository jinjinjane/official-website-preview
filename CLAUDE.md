## Project Overview

Jovida Official Website - A React-based marketing and user onboarding experience for the Jovida health assistant app. Built with React 18 + Vite 6, originally generated by Anima design-to-code platform and subsequently restructured.

**Primary Language**: Chinese (Simplified) - All user-facing content and documentation is in Chinese.

**Important**: This is a **frontend-only** project. The OAuth login flow is implemented on the frontend, but requires a separate backend service to handle authentication. The backend API endpoints (`/auth/google`, `/auth/apple`) must be deployed separately.

## Architecture

### Routing Structure
The app uses React Router v6 with the following routes defined in `src/App.jsx`:
- `/` and `/homepageh5` → HomePage
- `/login` → OAuth login page (Google + Apple)
- `/loginsuccess` → Post-login redirect
- `/message` → Message/chat interface
- `/pro` → Premium features
- `/privacy` and `/privacy-policy` → Privacy policy
- `/terms` and `/terms-of-use` → Terms of use

### Authentication Flow
OAuth integration managed through two providers:

1. **Google Sign-In**: Uses Google Identity Services OAuth2 code flow
   - Script loaded from `https://accounts.google.com/gsi/client`
   - Implements `initCodeClient` with popup UX mode
   - Returns authorization code to backend

2. **Apple Sign-In**: Uses AppleID JavaScript SDK
   - Script loaded from `https://appleid.cdn-apple.com/appleauth/static/jsapi/appleid/1/en_US/appleid.auth.js`
   - Popup-based flow with optional state/nonce
   - Returns both code and id_token

**Frontend OAuth flow** (`src/screens/Login/Login.jsx`):
1. User clicks provider button (Google or Apple)
2. Third-party OAuth SDK handles popup authentication
3. Frontend receives authorization code/token from provider
4. Frontend POSTs credentials to `${VITE_API_BASE_URL}/auth/{provider}`
5. **[Backend Required]** Server validates with provider and returns `{token, profile?}`
6. Frontend stores token in `localStorage.jovida.authToken`
7. Navigate to `/loginsuccess` with provider info

**Backend API Requirements** (not included in this repo):
- `POST /auth/google` - Accepts `{code, clientId, serverClientId?, redirectUri}`
- `POST /auth/apple` - Accepts `{code, idToken, state, user?, clientId, redirectUri}`
- Both endpoints should return: `{token: string, profile?: object}`

### Configuration
- **Auth config**: `src/config/auth.js` - Centralizes all OAuth settings from environment variables
- **Script loader**: `src/utils/loadScript.js` - Utility for dynamically loading third-party SDKs with caching
- **Responsive breakpoints**: `src/breakpoints.js` - Provides `useWindowWidth()` hook for responsive layouts

### Responsive Design Pattern
The app uses a custom hook-based responsive approach instead of CSS media queries:

```javascript
// src/breakpoints.js
const screenWidth = useWindowWidth(); // Returns current window width

// Responsive logic in components (typically in HomePage)
<div style={{
  minWidth: screenWidth < 750 ? "375px" : "1440px",
  // Other responsive inline styles
}} />
```

**Breakpoints:**
- Mobile: `screenWidth < 750px` (375px minimum width)
- Desktop: `screenWidth >= 750px` (1440px width)

This pattern allows per-component granular control with inline styles rather than global CSS media queries.

### Environment Variables
Required for OAuth (create `.env.local` in project root):
```bash
VITE_API_BASE_URL=https://api.your-domain.com

# Google OAuth
VITE_GOOGLE_CLIENT_ID=
VITE_GOOGLE_REDIRECT_URI=
VITE_GOOGLE_SERVER_CLIENT_ID=  # Optional, for backend verification

# Apple OAuth
VITE_APPLE_CLIENT_ID=
VITE_APPLE_REDIRECT_URI=
VITE_APPLE_SCOPE=name email     # Default if not specified
VITE_APPLE_STATE=               # Optional
VITE_APPLE_NONCE=               # Optional
```

Missing credentials will disable respective login buttons but won't break the app.

### Static Assets
- **Vite public directory**: `static/` (configured in `vite.config.js:7`)
- **All static resources must be in `static/` directory**, including:
  - Images: `static/img/`
  - Fonts: `static/fonts/`
  - Other assets referenced from HTML/CSS with absolute paths
- **Storybook static directory**: Configured to use `static/` directory (`.storybook/main.js:20`)

When referencing static assets in code, use absolute paths like `/img/filename.ext` or `/fonts/font.ttf` - these resolve from the `static/` directory at runtime.

**IMPORTANT**: Do not place static assets in `public/` directory - Vite is configured to use `static/` as the publicDir.

### File Structure Conventions
- **Screens**: `src/screens/{ScreenName}/{ScreenName}.jsx` - Each screen has its own directory with index.js, component file, and styles
- **Components**: `src/components/{ComponentName}/` - Reusable UI components with optional Storybook stories
- **Icons**: `src/icons/{IconName}/` - SVG icon wrapper components
- **Utils**: `src/utils/` - Shared utility functions
- **Config**: `src/config/` - Application configuration modules

## Development Notes

### Styling
- CSS modules are NOT used - each component has a corresponding `.css` file with global class names
- Style files are co-located with component files (e.g., `Login.jsx` + `style.css`)
- Design is pixel-perfect from Anima exports - maintain visual fidelity when making changes

### State Management
No global state management library (Redux/Zustand/etc.) is used. State is managed locally with React hooks or passed through React Router's navigation state.

### API Integration
All backend communication uses native `fetch` API. No axios or other HTTP client libraries are installed.

### Testing
No test framework is currently configured. When adding tests, consider using Vitest (compatible with Vite) or React Testing Library.

## Deployment Architecture

### Docker Configuration
The project uses a multi-stage Dockerfile optimized for production:

**Build Stage:**
- Base image: `node:18-alpine`
- Installs dependencies with npm cache
- Builds static files with `npm run build`
- Output: `dist/` directory

**Runtime Stage:**
- Base image: `nginx:1.25-alpine`
- Copies build artifacts to `/usr/share/nginx/html`
- Custom Nginx config for SPA routing
- Includes health check endpoint at `/health`
- Port: 80

### Nginx Configuration
Located at `nginx.conf`, configured for:
- **SPA Routing**: All routes fallback to `index.html` via `try_files`
- **Compression**: Gzip enabled for text/js/css/fonts
- **Caching Strategy**:
  - Static assets (images/fonts): 1 year
  - JS/CSS bundles: 1 year (with immutable flag)
  - index.html: no-cache (always fresh)
- **Security Headers**: X-Frame-Options, X-Content-Type-Options, X-XSS-Protection
- **Health Check**: `GET /health` returns 200 OK

### GitLab CI/CD Pipeline
Pipeline stages defined in `.gitlab-ci.yml`:

1. **lint** - Build verification
   - Runs `npm ci` and `npm run build`
   - Uses cached `node_modules/`
   - Triggers on all commits

2. **image-push-hk-dev** - Dev image build (Hong Kong registry)
   - Builds Docker image with `IMAGE_TAG_DEV`
   - Pushes to `sea-registry.us-east-1.cr.aliyuncs.com/vita/ha/official_website`
   - Triggers: Manual or commit title contains `image-push` (release branches)

3. **image-push-us-prod** - Prod image build (US registry)
   - Builds Docker image with `IMAGE_TAG_DEV`
   - Pushes to US East registry
   - Triggers: Manual or on `release-*` tags

4. **deploy-dev** - Deploy to dev environment
   - Uses `dev-ci-ucenter-cn` runner
   - Executes `/deploy/run.sh dev ${IMAGE_TAG_DEV}`
   - Triggers: Commit title contains `deploy-dev` or `deploy-both`

5. **deploy-us-east-test** - Deploy to test environment
   - Uses `us-east` runner
   - Executes `/deploy/run.sh test ${IMAGE_TAG_DEV}`
   - Triggers: Commit title contains `deploy-test` or `deploy-both`

**Image Naming Convention:**
- Registry: `sea-registry.us-east-1.cr.aliyuncs.com/vita/${CI_PROJECT_PATH}`
- Dev tag: `dev-${BRANCH_NAME}-${SHORT_SHA}`
- Prod tag: `${TAG}-${SHORT_SHA}` (requires `release-*` tag)
